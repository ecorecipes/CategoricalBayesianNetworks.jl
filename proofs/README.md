# Finite typed open networks and stochastic interpretation: Lean 4

This independent categorical layer proves an actual **syntax category**, with
Mathlib `Category`, `MonoidalCategory`, `SymmetricCategory`, and
`CopyDiscardCategory` instances. Equality is precisely structural isomorphism,
not numerical equivalence or a relation generated by the desired laws.

For an arbitrary typed mechanism signature, interfaces are finite typed sets.
Networks have arbitrary output maps, injective input maps identifying exactly
the exogenous variables, ordered parent lists with possible repetition, and
finite acyclic internal syntax. Copied outputs, pass-through variables, empty
interfaces, and hidden components are retained.

The numerical layer now constructs their **actual finite sum-product
interpretation**, proves normalization and structural-isomorphism invariance,
and packages it as a **strong braided monoidal functor into the existing
FiniteKernels FinStoch category**, preserving copy and discard. It supports
arbitrary finite signature-state types, including empty types; required
generator-state inhabitance is derived for each given input assignment, not
silently assumed.

## Build and inspect

```sh
lake build --wfail
make audit
make check-certificates
make docs
```

Lean, Mathlib, and mdgen are pinned to **4.30.0**. The Lake manifest shares
`../../.lake-packages` with the ecosystem. Path dependencies on
`FiniteKernels.jl/proofs` and `BayesianNetworks.jl/proofs` supply the existing
FinStoch category and the finite DAG product-normalization theorem. This work
does not change those projects or the existing schema emitter/JSON. Proof CI
checks out the dependencies as sibling packages.

`make audit` kernel-checks the headline declarations, uses `assert_no_sorry`,
and fails unless every printed axiom belongs to
`{propext, Classical.choice, Quot.sound}`. It rejects an empty expected inventory,
requires the executable entry point, scans every root Lean file and recursively
scans the library modules. Eight synthetic driver-guard regressions run afterward.
The Markdown, HTML and **complete**
PDF are generated from the Lean module documentation and code by mdgen, pandoc,
and LuaLaTeX. Graphviz generates the example diagram. Publication uses the
workspace JuliaMono fonts and STIX Two Text.

## JSON certificate command

```sh
lake exe check_certificate certificate-fixtures/mixed.json
```

The executable reads `OpenNet.RawCertificate/v1`, rejects missing/unknown fields,
bad tags, out-of-range indices and malformed JSON, and calls the unchanged
proved `Network.check`. Exit codes are 0 for accepted data, 1 for parse/schema/
certificate failure, and 2 for usage or file-I/O failure. Integer tokens are
required; fractional and exponent notation—including `1.0`—are deliberately
rejected rather than coerced.

`make check-certificates` runs the real `lake exe` entry point and 64 compiled
CLI regression cases. `JSON.read_sound` proves accepted records are valid;
`read_preserves_decoded` proves checking does not replace their values.
Bounded integer, reference and state-row decoding have round-trip/value lemmas.
`JSON.checkedNet` connects accepted records to the existing syntax normalization.
This does not prove the Julia exporter, the compiler/runtime, or complete
correctness of JSON lexical processing; see [JSON-REPORT.md](JSON-REPORT.md).

## Important scope boundaries

The mathematical composition is total on matching interfaces. The frozen
runtime-v1 Julia name-safe `compose` wrapper can reject matching interfaces
because `_validate_composite` also enforces global unique names when both
operands were uniquely named. Runtime v1 also exposes `compose_structural`
without that freshness restriction. Neither wrapper's Julia implementation is
kernel-verified here; the mathematical gluing and quotient laws are proved.

A signature type can encode variable names, ordered state data and references;
a mechanism label can encode its name/reference and its input/output attribute
profiles. The new [certificate interface](CERTIFICATE.md) makes these records
concrete and checks finite position, reference, interface and rank constraints.
It does not verify a parser/exporter from Julia ACSets, Catlab's concrete
pushout implementation, Julia's expression compiler, or floating-point
arithmetic. `enumerated_table_correct` instead proves the exact finite
enumeration formula independently of any Julia runtime.

Hidden mechanisms survive discard, so this syntax is not given a
`MarkovCategory` instance. The concrete theorem `Examples.discard_not_natural`
shows why such an instance would be wrong.
The normalized interpretation may erase hidden mechanisms semantically;
`Interpretation.semantic_discard` proves this without changing syntactic
equality.
